# Resume Analyzer AI

Проверка резюме на совместимость с системами отбора (ATS) и на то, что увидит
рекрутер за первые шесть секунд. Разбор выполняется полностью в браузере: файл
никуда не загружается.

**[Открыть приложение](#запуск)** · [Архитектура](#архитектура) ·
[Движок](#движок-анализа) · [Решения](docs/adr)

Два режима: проверка своего резюме и скрининг пачки кандидатов под одну вакансию.

---

## Что это решает

Три четверти резюме отсеиваются автоматикой до того, как их прочитает человек.
Причины почти всегда механические: двухколоночная вёрстка, из-за которой парсер
получает перемешанные строки; контакты в колонтитуле, которые часть систем
игнорирует целиком; описания обязанностей вместо результатов.

Существующие проверщики называют проблему, но не показывают, где она в тексте, и
ломаются на резюме, написанном не по шаблону. Здесь оба случая закрыты:

- каждое замечание привязано к конкретным символам в тексте и подсвечивает их;
- резюме без единого заголовка разбирается по содержимому — по датам, спискам и
  словарю, а не по ожидаемой структуре.

## Что проверяется

Шестьдесят правил в семи измерениях. Каждое правило отвечает на четыре вопроса:
что найдено, почему это стоит кандидату собеседования, что сделать, и как это
выглядит после исправления.

| Измерение              | Вес | Что внутри                                                                             |
| ---------------------- | --- | -------------------------------------------------------------------------------------- |
| Читаемость для ATS     | 26% | Текстовый слой, колонки, таблицы, колонтитулы, надписи, шрифты, лигатуры, графика      |
| Структура              | 18% | Обязательные разделы, контакты, ссылки, объём, обратная хронология, датировка опыта    |
| Содержание             | 24% | Квантификация достижений, глаголы действия, штампы, пассив, первое лицо, длина пунктов |
| Совпадение с вакансией | 14% | Обязательные и желательные требования, соответствие должности и грейда, аббревиатуры   |
| Карьерная история      | 8%  | Перерывы, частота смены работы, рост в должностях, актуальность                        |
| Язык и оформление      | 5%  | Единообразие дат, маркеров, времён, читаемость, смешение языков                        |
| Международный рынок    | 5%  | Защищённые персональные данные, уровень английского, релокация, локальный контекст     |

Измерение, в котором не выполнилось ни одного правила, исключается из среднего, а
не считается за сотню. Без вакансии все правила совпадения пропускаются, и их вес
перераспределяется: резюме не наказывается за сравнение, которое пользователь не
просил.

## Режим рекрутера

Загружаете описание вакансии и до 25 резюме разом. Список выстраивается по
соответствию: покрытие обязательных требований весит больше всего, потому что
это и есть заданный вопрос. Аккуратное резюме не поднимет кандидата, у которого
нет половины must-have — чистое резюме не на ту роль остаётся не той ролью.

Ранжирование раскладывается на составляющие, чтобы список не приходилось
принимать на веру. Разобранные документы хранятся в памяти, поэтому смена
вакансии пересчитывает весь шортлист за миллисекунды, не перечитывая файлы.

Пометки в колонке «на что обратить внимание» сформулированы как вопросы, а не
как приговор. Перерыв в опыте — повод спросить на скрининге, а не причина
отказать; инструмент, которым просматривают сорок резюме за раз, влияет на
поведение в масштабе.

## Слой рекомендаций

Опциональный и включается по кнопке на конкретном замечании, а не сам по себе.
Детерминированный отчёт полон без него, а отправка текста модели — пусть и
обезличенного — должна быть осознанным решением, а не побочным эффектом
раскрытия карточки.

Модель не оценивает резюме. Оценка — работа движка, и балл, который изменился
потому, что модель сегодня настроена иначе, ничего не стоил бы. Модель делает
единственное, в чём она действительно сильнее: превращает плоскую строку в
резкую. На вход уходят только те строки, на которые указывает замечание.

Ничего не применяется автоматически. Варианты показываются рядом с оригиналом и
копируются вручную: формулировку, которую кандидат не прочитал, он не защитит на
собеседовании.

Вендор спрятан за интерфейс `LlmProvider`, запрос и ответ валидируются одной и
той же zod-схемой на обеих сторонах, эндпоинт ограничен по частоте. Без ключа
кнопка не показывается вовсе, а не появляется и падает при нажатии.

## Приватность

Это продуктовая гарантия, а не оговорка в футере.

- Файл читается в память браузера и разбирается там же. Ни один байт не уходит
  на сервер — ни в аплоад, ни в телеметрию.
- Слой рекомендаций через языковую модель (опциональный) получает текст с
  вырезанными персональными данными: имя, почта, телефон и ссылки заменяются на
  плейсхолдеры и восстанавливаются в ответе.
- Перед каждым исходящим запросом выполняется `assertRedacted`, который бросает
  исключение при утечке. Ошибка редакции должна падать громко, а не утекать тихо.
- Это покрыто тестами: имя, почта, телефон и ссылки не должны встречаться в
  обезличенном тексте, а подстановка должна возвращать их обратно.

Подробнее: [ADR 0003 — граница приватности](docs/adr/0003-privacy-boundary.md).

## Архитектура

Feature-Sliced Design, границы слоёв проверяются линтером, а не соглашением.

```
app/                    Next.js App Router: только тонкие route-файлы
src/
  views/                композиция страниц       → widgets, features, entities, shared
  widgets/              самостоятельные блоки UI → features, entities, shared
  features/             пользовательские сценарии → entities, shared
  entities/             предметная область        → shared, @x других сущностей
  shared/               ядро без доменных знаний  → shared
```

Слой `pages` назван `views`, чтобы Next.js не принял его за Pages Router.

`eslint-plugin-boundaries` проверяет три инварианта: порядок слоёв, единственный
публичный API у каждого слайса и кросс-импорты между сущностями только через
сегмент `@x` (FSD 2.1). Нарушения падают в CI. Правила уже ловили реальные
ошибки — например, виджет, композирующий другие виджеты.

### Ключевое разделение

`ResumeDocument` — шов, на котором держится всё остальное. Движок, UI и тесты
читают только его и ничего не знают о форматах файлов. Поддержка нового формата —
это новый экстрактор и больше ничего.

```
файл → extract (pdf | docx | text) → RawExtraction
     → segment + parse              → ResumeDocument
     → analyse                      → AnalysisResult
```

Движок — чистый TypeScript без зависимостей от фреймворка: одинаково работает в
браузере, на сервере и в тесте.

## Движок анализа

Детерминированный: один и тот же документ всегда даёт одинаковый балл, одинаковые
замечания и одинаковый порядок. Без этого показывать число было бы нечестно.

Скоринг вычитанием. Каждое измерение начинается со ста баллов и теряет их по мере
срабатывания правил. Правило, которое неприменимо, исключается, а не засчитывается
как пройденное — резюме не получает баллов за проверку, которая не выполнялась.

Добавить правило — это один объект в одном массиве. Движок находит его сам,
скоринг подстраивается, UI отрисовывает что пришло.

```ts
{
  id: 'bullets-not-quantified',
  dimension: 'content',
  severity: 'critical',
  penalty: 40,
  title: 'В достижениях нет цифр',
  why: 'Без числа утверждение невозможно проверить и не с чем сравнить…',
  fix: 'Добавьте измеримый результат хотя бы в половину пунктов…',
  evaluate: ({ resume, metrics }) => { /* … */ },
}
```

## Извлечение

**PDF** — через pdf.js. Текстовые фрагменты приходят в порядке отрисовки, поэтому
для двухколоночной вёрстки колонки чередуются; они перегруппировываются по базовой
линии и пересортировываются по координатам. Многоколоночность определяется по
реальному вертикальному «жёлобу» — полосе, которую не пересекает ни одна строка, —
а не угадывается по шаблону.

**DOCX** — разбор OOXML напрямую через `fflate`, без конвертации в HTML.
Конвертер выбрасывает ровно то, что здесь нужно: какой текст лежит в таблице,
какой в плавающей надписи, задана ли секция в две колонки и какими шрифтами.

**Текст** — запасной путь для PDF без текстового слоя.

## Тесты

```
npm test          # 76 тестов
npm run verify    # typecheck + lint + tests
```

Тесты прогоняют настоящий конвейер целиком, а не отдельные правила в изоляции:
движок может пройти все юнит-тесты и при этом ранжировать резюме бессмысленно.
Фикстуры синтетические — резюме это персональные данные, и тестовый набор
последнее место, где им быть.

Набор окупился сразу, найдя три настоящих дефекта. Самый показательный: `\b` в
JavaScript определён через ASCII-символы, поэтому `/\bдата\b/` не находит ничего.
Двадцать восемь шаблонов в семи файлах были мертвы — весь русский словарь.
Английские работали, поэтому баг был невидим.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:3000

Языковая модель опциональна — детерминированный движок работает без неё. Чтобы
включить слой рекомендаций, скопируйте `.env.example` в `.env.local` и заполните
`LLM_PROVIDER`, `LLM_API_KEY` и `LLM_MODEL`. Доступ к модели спрятан за интерфейс
`LlmProvider`: смена вендора — это один файл адаптера.
